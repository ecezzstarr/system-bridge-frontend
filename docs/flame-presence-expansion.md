# Flame Presence — Client world expansion contract

## Institutional truth
WEAVE owns Flame completely as its institutional intelligence architecture. Eight, River, Echo and specialized File Folder Flames are distinct types of that company intelligence. The Client owns the enterprise and File Folder, not Flame, and remains the source of direction. Native File Folder operations are performed by WEAVE Flame under authenticated owner instructions; no external model is required for those operations. Model-assisted conversation is not itself authorization to execute or spend. The Lord or Lady is not required to personally operate every business task. Administration, Forensics, Mandate, Attorney, Bridgers and Legions carry their assigned responsibilities. AI Presence participates within those boundaries, not above them.

## Current implementation versus intended capability
- AI File Folder identities and product/build actions already exist in the repository.
- Identity, a Customer Door label and a published product do **not** establish external publishing, prospect conversations, sales or recurring AI execution.
- Ember Works is an initial Flame AI identity; do not label it as a live autonomous sales agent until the actual connection, authorization and executor are verified.
- The TypeScript contract in `lib/flame-presence-expansion.ts` models authority, connections, movements and readiness. It is not itself a scheduler, API integration, database migration or live agent.

## Required movement
1. Administration approves a scoped, expiring mandate for an AI identity and a Client File Folder.
2. Mandate validates countries, products, budget, connections and authorized actions.
3. Each provider connection is verified; secrets stay server-side and are never exposed to the File Folder browser.
4. A durable job queue and scheduled worker claim work, retry transient failures and record immutable provider references.
5. Research and creative output become proposals. Publication requires Client authorization and platform permissions.
6. Incoming opt-in enquiries are attributed to the correct Customer Door, with human Bridger/Legion handoff when needed.
7. Forensics independently verifies orders, payments and receipts; an AI claim is not a settled sale.
8. The Client sees verified progress, unresolved work and exceptions within their world.

## Non-negotiable acceptance checks
- Restarting the worker does not erase unfinished work or duplicate publication.
- Disconnected accounts cannot be represented as live.
- A revoked/expired mandate stops new external actions.
- No AI can approve its own settlement, impersonate a person or promise a sale.
- Each activity is attributable to the AI identity, Client, position, provider and order where applicable.
- Mobile File Folder shows honest states: identity, awaiting mandate, connections needed, ready, active, paused.

This foundation precedes any claim of globally autonomous expansion.

## Personal Flame
Every active WEAVE account can access a personal interaction surface independently of departmental authority. WEAVE owns the intelligence; the account holder directs personal use. Native reflection, presence explanations and personal notes use no external model. Advanced conversation is optional, uses River's provider capability only with explicit user consent, and receives only the current input and recent model-enabled turns, not native notes or enterprise records. The first release uses a temporary daily allowance of 20 model requests per account (UTC), no wallet debit, and stores personal turns separately by authenticated user. Clearing personal history removes these stored turns, not provider records or backups. Personal Flame has no administrative, financial, or enterprise mutation tools. The shared header exposes it across authenticated staff and Client surfaces. This is an initial implementation; full production verification and richer native reasoning remain required.

## Flame in motion
The shared Personal Flame host persists across internal route navigation. Explicit open/go to/take me to instructions navigate automatically only to a unique exact registered title or path within the authenticated runtime role; ambiguous requests return linked directions. Native adapters inspect daily prospect claims, Agent distribution and Client File Folder snapshots. An explicit claim my daily free prospect instruction invokes the existing authenticated free claim transaction; Flame does not send messages or assert contact validity. Workshop results are distinguished from suggestions, failures and route transitions; links preserve the original access gates. No model can invent an executable action or arbitrary URL. Further adapters require explicit scope, validation and independently verifiable results. Existing controls remain available.

The interaction interface previews supported operations without mutation, opens the registered workshop, and submits the original explicit instruction only after the destination route is observed. The Prospect Claim surface re-reads the original record on a confirmed Flame movement. A route transition alone is not an access or completion claim; the server rechecks authority and existing endpoint results. An interrupted or rejected route does not submit the queued operation.

## Usage subscription
One account-level prepaid allowance covers personal and File Folder Flame, including the shared Pro File Folder engine. Administrations pays no usage units. Navigation and previews are free; native replies use 1 unit, model replies use 5, and registered workshop operations use 2. The priced plans are Flame Go ($3 for 300 units), Flame Plus ($9 for 1,200 units), and Flame Pro ($39 for 6,000 units). Each grants prepaid units rather than a time-limited subscription; these prices and usage weights are initial tariffs, not a promise of equivalent external-model capacity or profitability. Units do not expire or renew automatically. Successful top-ups transfer the quoted legacy TRX wallet amount to the existing company settlement wallet in a transaction with two ledger entries and a purchase reference; USD pricing is converted using a live quote and the buyer's authorized maximum. Existing material, construction and other operational charges remain separate. Old File Folder reply debits are replaced, not stacked. Failed operations release reserved units; interrupted settlement may leave a reservation for reconciliation. Purchase receipts are represented by purchase and ledger records, not an independent receipt service. The existing daily model safety allowance for non-admin personal conversation remains separate from billing. This first implementation covers registered Flame surfaces, not all historical AI endpoints.
