# WEAVE private workshops and shared world

A Client File Folder is an owned operating environment. Its work moves from Blueprint to Parts, Formation, Operation, and a Customer Door. Interiors must connect to the existing authorized tools, purchases, receipts, and construction records. A room is never an alternative ownership or wallet system.

Staff enter through System Switch with their own identity. Public Customer Doors and Flame Event are meeting spaces. Access to a private workshop must be an explicit, server-checked invitation with a bounded role; public presence never grants access to Client records.

Implemented in this refinement: small articulated worker with movement-driven gait; walkable workshop interior with collision walls, shelves and workbench; phone directional controls and drag look; proximity interaction connects to existing tools. Shared worker geometry is used by both Client and staff walking worlds. Actual renderer QA uses labeled synthetic Client data and does not verify transactions.

The subsequent shared System Switch implementation adds authenticated public presence, remote avatar interpolation, disconnect cleanup, real published Customer Doors and concurrent-operation tests. See system-switch-shared-world.md. Private workshop invitations and shared private-task authority remain future work. Client stories mean Client branding, rather than fictional narratives. The original reference image remains an unfinished visual target.

Validation: phone renderer confirmed workshop entry, movement until Use workbench became available, and activation of the existing tools callback. Existing workflow regressions passed. Build/type results are recorded separately in the work logs. No deployment for this refinement.
