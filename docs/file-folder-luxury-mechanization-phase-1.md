# File Folder luxury environments — Phase 1 (Plus proof)

## Product direction
A Client's purchased File Folder must feel like receiving a substantial enterprise environment, not a simple dashboard or a decorative castle. The company homepage and shared Weave Open World remain unchanged; this phase advances the private File Folder architecture.

### Implemented in this phase
- Added reusable first-party physically based porcelain/marble and brushed-gold surface materials. Their existing approved color assets provide the diffuse finish; small, cache-shared normal and roughness textures are generated locally for visual detail. No external asset host, AI provider, subscription or customer data source was added.
- Added physical equipment to each Plus station: machined service gears and support rails, a construction gantry linked to an actually recorded in-progress build, and a visible operational signal only where a real active system record exists.
- Mechanical motion is bounded, respects reduced-motion preference, and is idle without recorded work. Client construction percentage controls the modeled assembly height. These animations are representations of actual stage, not claims that machinery performs a real-world physical operation.
- Preserved all six authorized Plus work areas, existing tier entitlements, File Folder prices, inventory, customer doors, employee permissions and construction timestamps. No sales, balances or credits are generated by rendering.

### Limitations and next phases
This is **not yet a photographic match** to the official Plus File Folder art. The large architecture still uses procedural primitives; true high-resolution normal/metalness/roughness sets, authored geometry, realistic glass and water, physically calibrated reflections, interior equipment and a coherent material-library import pipeline remain future work. The shared CityMaterial atlas remains unchanged, so Standard, Pro and Premium visual results are preserved by this first release.

The test contract checks record-gated machinery, local assets, maps and compatibility. It does not prove GPU frame rate, visual quality or authorized client operating flows. Release review must compare screenshots against the official art on representative Android phones and desktop, including reduced-motion mode, poor GPU fallback, build-to-commissioning state changes and inactive Client accounts.
